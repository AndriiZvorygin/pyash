# Rust-GPU VLIW Targets

The VLIW GPU targets share the semantic implementation in
`rust/pyac-vliw-core`. Rust-GPU compiles it into one Vulkan SPIR-V module for
the native Housekeeper worker and generated WGSL for the browser pack runtime.
Keep behavior changes in the shared Rust core; do not add a parallel CUDA/PTX
or hand-maintained WGSL implementation.

## Build and smoke-test

Install the repository's pinned Rust toolchain, the official `cargo-gpu`
0.11.0 release, and its matching nightly/Rust source component. Then run:

```sh
./rust/pyac-gpu/build-kernels.sh
rust/pyac-gpu/smoke.sh
```

The smoke command runs the canonical `.pyac` fixture and all ten named-slot
function operators on a discrete Vulkan GPU, then asserts the returned values.
It requires an NVIDIA device visible to Vulkan. The browser build consumes the
WGSL generated by the same script.

## Housekeeper jobs

The `vliw` runtime supports two payload forms:

- `pyac-pack-execute` transports a canonical `.pyac` pack as base64 and
  returns typed sentence values.
- `vliw-batch-evaluate` transports bounded named-slot candidates and cases,
  returning evolutionary fitness and outputs.

Both forms execute in `pyac-vliw-gpu-worker` and call the same no-std Rust
semantic core. The Housekeeper performs GPU admission and routing before the
worker dispatches Vulkan compute. Candidate and pack limits are validated
before device buffer allocation. A missing/discrete-less GPU is a hard failure;
the evaluator does not silently switch to a second semantics implementation.

The GPU Housekeeper Compose service builds the worker into its image and mounts
the host NVIDIA Vulkan ICD manifest read-only. The default manifest path is
`/usr/share/vulkan/icd.d/nvidia_icd.json`; set `NVIDIA_VULKAN_ICD_PATH` when the
host stores it elsewhere. The image includes `libegl1`, `libvulkan1`, and the
X11 runtime libraries required by NVIDIA's Vulkan ICD.

## Current boundary

This is a shared implementation for the supported VLIW slice, not full Pyash
interpreter parity. The `.pyac` path covers the Rust core's currently decoded
scalar, date, numeric/bool vector, and bounded equality-conditional groups.
Named-slot candidate evaluation covers bounded straight-line functions with
the ten registered numeric operations. Text-vector handling and broader Pyash
control flow remain outside this GPU slice. See
[`pyash-vliw-compiler-architecture.md`](../../documentation/reference/pyash-vliw-compiler-architecture.md)
for the broader compiler/runtime boundaries.
